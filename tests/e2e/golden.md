# E2E 黄金用例（真实生成）

前置：`npm run dev`（或 `scripts/serve.sh`）+ `npm run worker` 已运行；`.env` 已配 `DASHSCOPE_API_KEY`；基础镜像 `ivanatoms/base:node22` 已构建。

由「测试验证」子代理用 browser-use 执行；每条记录 pass/fail + 截图/控制台日志/URL。

## 用例 1：待办/追踪（app，含持久化）
1. 首页输入：「一个待办清单 app，可以添加、勾选完成、删除任务，并持久保存」→ 开始生成。
2. `/chat/{id}`：SSE 进度从 build→run→ready；出现 iframe 预览。
3. 预览内：添加 2 条任务、勾选、删除 1 条 —— 交互正常。
4. 刷新预览（或停/起 run 容器）后数据仍在（`DATA_DIR` JSON 持久化）。
5. 点「发布」→ 访问 `/p/{slug}` 可打开且数据可见。
判据：主流程可用、数据持久化成立、公网路径可达。

## 用例 2：预约/联系表单（website/app，迭代不丢数据）
1. 输入：「一个预约/联系表单页面，提交后展示最近的提交记录」→ 生成。
2. 提交一条表单 → 列表出现该记录。
3. 在对话里：「表单再加一个『电话』字段」→ 迭代构建成功。
4. 刷新：之前提交的数据仍在。
判据：迭代成功、原子切换不打断、历史数据保留。

## 用例 3：浏览器小游戏（game）
1. 输入：「一个贪吃蛇网页小游戏，方向键操作，纯前端」→ 生成。
2. 预览可玩，键盘可控，控制台无致命错误。
3. 对话：「把速度调慢一点、背景改成深色」→ 迭代后仍可玩。
判据：可玩、无致命报错、迭代后回归正常。

## 异常用例：无意义/超长输入
1. 输入乱码或超长文本 → 系统给出友好降级（提示或生成通用占位页），不崩溃、不卡死。
判据：不 500、不无限构建。

## 健康冒烟
- `GET /api/health` → `db:ok`，`isolation` 合理，`backlog` 正常回落。
