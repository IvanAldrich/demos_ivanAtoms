## 1. atoms.dev 产品介绍

### 1.1 产品定位

Atoms（前身 MGX）由 Foundation Agents / DeepWisdom（MetaGPT 开源团队）推出。一句话定位：

> 把想法变成可销售的产品 —— AI 员工用于验证想法、构建产品并获取客户，几分钟内完成，无需编码。

它把「Vibe Coding（氛围编程）」推进到「Vibe Business（氛围创业）」：不仅生成代码，还覆盖**市场调研 → 产品规划 → 架构设计 → 全栈构建 → 发布上线 → SEO/广告增长**的完整链路。

### 1.2 目标用户与典型场景

- **非技术或弱技术创业者**：有想法、没有工程团队，需要 MVP 快速上线验证。
- **独立开发者 / 小团队**：把重复的脚手架、后台、支付、部署工作交给平台。
- **增长驱动型项目**：需要 SEO 页面、广告投放、数据分析一并内建。
- **企业创新/验证团队**：低成本试错多个产品方向（Race Mode 多模型并行比稿）。

典型任务：SaaS 落地页、独立品牌电商、小游戏、内容/视频工具、预约与表单类应用、内部工作台。

### 1.3 产品矩阵（4 个站点 + 1 个后端）

| 站点 | 角色 | 技术栈 |
|---|---|---|
| `atoms.dev` | 营销主站 + 产品入口（登录、定价、模型、模板、发现、用例、对比、提示词） | Nuxt 3 SSR |
| `app.atoms.dev` | 用户生成应用的托管域，每项目独立子域 `{projectId}-{hash}--latest.app.atoms.dev` | 泛域名托管 |
| `router.atoms.dev` | 独立产品「Atoms Router」：多模型统一 API 网关（38 模型，Anthropic/OpenAI 兼容，钱包计费） | 独立 SPA |
| `help.atoms.dev` | 帮助中心（13 个文档板块，含 changelog） | Next.js App Router |
| `console-backend.deepwisdom.ai` | SEO 内容平台后端（营销页内容管理） | 内容 API |

工程上值得注意：**营销站（SEO 优先）、产品工作区、帮助中心、模型网关彼此独立部署**，共享品牌与 CDN，互不拖累发布节奏。

### 1.8 面向研发的取舍与启示

1. **营销与产品分离**：营销站 SSR 极致 SEO，工作区独立路由，性能与迭代互不绑死。
2. **内容平台化**：程序化 SEO 页由 CMS/API 驱动，前端只渲染，便于批量生成与多语言。
3. **每项目子域发布**：泛域名 + 项目隔离，发布即生效，hash 版本 + `--latest` 别名天然支持回滚。
4. **增长内建**：SEO / Ads / 分析作为一等 Agent，而不是事后接第三方工具。
5. **证据边界**：工作区登录后交互未实测，本文相关描述来自公开文档与路由推断，做技术评估时应按「已知/推断」区分。

## 2. IvanAtoms 产品介绍

### 2.1 产品定位

IvanAtoms 是在逆向 atoms.dev 之后，**按核心功能等价重建**的演示级全栈 AI 建站平台。核心闭环一句话：

> 用户用自然语言描述产品 → AI 生成多文件 Node/npm 全栈代码工程（前端 + 后端 + 数据持久化）→ Docker 沙箱构建并自动修复 → 一键发布为公开 URL → 对话迭代后重建、原子替换上线。

与 atoms.dev 的差别是**工程取向**：不做多智能体叙事、不做计费与增长闭环，而是把「生成 → 构建 → 修复 → 发布 → 迭代」这条链路做扎实、可观测、可验证，作为可运行、可改造的技术样本。

### 2.2 目标读者与使用场景

- **AI 工程学习者/研究者**：理解「AI 建站平台」从 prompt 到线上 URL 的完整机制。
- **平台开发者**：以本仓库为基线，扩展多模型、多 Agent、计费、托管等能力。
- **技术评审/面试演示**：用真实可运行的闭环展示代码生成、沙箱隔离、队列、运行时治理。
- 不适用：直接商用、承载真实用户数据、多租户高可用部署（见 2.9 已知边界）。

### 2.5 技术架构

```
Browser
  ├─ 控制面 Next.js（auth / projects / publish / SSE）
  └─ /p/{slug}、/preview/{projectId}/{token} → 反向代理 → 运行时容器 IP

控制面 ──> 数据库（SQLite/Prisma：users/projects/messages/
  │        versions/build_jobs/build_events）
  ├─ 入队 BuildJob（幂等，messageId 唯一）
  ▼
独立 worker 进程（npm run worker）
  │  claim + lease + heartbeat + 重试
  ▼
Sandbox Provider（Docker）
  ├─ 构建：npm install / build / 启动验证 / 资源冒烟
  ├─ 运行时：每个 project-version 一个容器
  └─ 产物：storage/projects/{id}/snapshots/v{n}
```

- **控制面**：Next.js 15 App Router + React 19 + TypeScript；营销面与工作区用路由组隔离；内置 `http-proxy` 反代。
- **数据**：Prisma + SQLite，宿主侧存用户/项目/消息/版本/构建任务/构建事件；每项目工程与运行数据存独立目录（含项目自有数据）。
- **异步执行**：Web 与 worker 是两个进程，通过**持久队列**解耦，避免长构建拖垮请求。
- **模型接入**：OpenAI 兼容 SDK，配置 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 即可换网关（当前环境接百炼 `deepseek-v4.1-flash`，关闭 thinking 以避免推理 token 挤占输出预算）。
- **i18n**：next-intl，zh/en 双语言，路由前缀 + 每语言 sitemap。

### 2.6 生成管线（平台核心）

#### 2.6.1 模块化生成：Profile + Manifest 驱动的两层生成

问题背景：若只给「4–12 个文件」的松散约束，模型容易产出 30–80KB 的单文件，导致迭代时上下文截断、EDIT 精确匹配失败、修复轮爆炸。

解决方式：把「模块化」从提示词建议升级为**可校验的架构约束**。

1. **Profile**：按网站类型（通用网站、CRUD、工作台、落地页、API 服务、小游戏）提供架构模板。
2. **Module Manifest**（落盘 `.atoms/manifest.json`）：规划阶段输出结构化模块清单——路径、职责、`exports` 签名、依赖、大小预算。
3. **文件预算硬门禁**：代码文件 soft 10KB / hard 16KB，`index.html` ≤ 4KB，内联 JS/CSS ≤ 2KB（可通过环境变量调整）。
4. **依赖拓扑分层生成**：按依赖层级依次生成；单文件生成时**只注入其依赖模块的 exports 签名**，不再附带上游整文件。层内默认串行——让后生成的模块能看到上游已落盘的**真实接口**，避免 DOM id / 签名 / 状态字段漂移；可用 `MODULAR_GEN_CONCURRENCY` 放开并发。

关键工程原则：**凡跨模块依赖，必有机器可验证的契约**——不依赖模型「理解」来保证模块一致性，而是用 manifest exports 做契约校验。

#### 2.6.2 迭代：上下文组装（Context Assembler）

- 依据 manifest、最近编辑与需求关键词，选择 **1–3 个目标文件**及其依赖签名（≤24KB），替代旧的全量注入。
- 优先使用 **SEARCH/REPLACE** 增量编辑；新增 `### NEED:` 按需读取协议与 EDIT 失败重读重试。
- 超限文件自动触发 Split Agent：基于 TypeScript AST 搬移符号、保持公共 API，最多两次尝试。
- 存量无 manifest 的工程首次迭代时，自动生成启发式 manifest。

#### 2.6.3 确定性与自修复

```
生成
  ▼
结构门禁（在 npm install 之前，确定性）
  ├─ 文件大小 / 内联代码
  ├─ import 图 / 入口可达性
  ├─ manifest 漂移
  └─ ESM 规范
  ▼ 失败 → 结构化 violations 直接回传（不浪费一次构建）
语法校验（一次容器启动，批量 node --check）
  ▼
沙箱构建：npm install → npm run build → 启动验证 → 资源冒烟
  ▼ 失败
自修复：错误尾部 + 结构化 violations + 原始需求 → LLM 修复（生成+构建+修复总尝试上限 5 次）
  ▼ 全部门禁通过
版本落账：写入 app_versions
```

原则：**确定性检查优先于 LLM 修复**。能被机器精确定位的问题，就不让模型重新理解整个工程。修复轮还会把 reviewer 的自然语言反馈做二次结构化解析，扫描提到的文件并补充结构化发现，提升收敛率。

### 2.7 隔离与安全

**容器模式（默认 `RUNTIME_ISOLATION=container`）**

- 非 root（`1000:1000`）、只读 rootfs、`/tmp` 为 tmpfs。
- `--cap-drop ALL`、`no-new-privileges`；pids / 内存 / CPU 限额（默认 512 / 2048MB / 2 CPU）。
- 只挂载项目工作目录，不挂载宿主目录、不注入宿主环境变量。
- 运行时使用 internal 网络，宿主可访问容器 IP，容器无外联；构建期 bridge 网络（npm registry 需要）。
- 启动时校验 `docker info` 真实可用，否则 health 明确报告 `process + degraded`，**不假装容器隔离**。

**进程模式**：仅显式本地开发降级，无内核级隔离，不能运行不可信代码。

**平台侧防护**

- 密码 scrypt 加盐哈希；会话 Cookie host-only + `SameSite=Lax`；生产开启 `COOKIE_SECURE` 时用 `__Host-` 前缀。
- 预览令牌 HMAC + 过期时间（默认 24h），无效/过期返回 401。
- `/api/*` 非 GET 请求校验 `Origin`，跨源写直接 403。
- 反代转发前剥离平台会话 Cookie 与上游同名 `Set-Cookie`，生成应用无法读取/覆盖平台会话。
- 配置 `APP_BASE_DOMAIN` 后应用走独立子域，与平台不同源，生成页面的 JS 无法调用平台 API。
- 安全响应头：`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy`、`X-Frame-Options`。

### 2.8 队列、运行时与可观测性

**持久队列**

- `BuildJob` 状态机：`queued → leased → running → done/failed`，带租约、心跳、最大重试；worker 崩溃后租约过期可重新领取。
- `BuildEvent` 落库，SSE 轮询回放；不依赖单进程 EventEmitter，多实例/重启后事件不丢。

**运行时**

- 每个 `project-version` 一个容器；发布/迭代采用**暂存启动 → 健康检查 → 原子切换**，失败不影响线上版本。
- 删除项目会停止容器并清理磁盘。
- 启动对账：中断构建标记失败可重试；孤儿容器按 label 清理；已发布项目按 `run.json` 恢复。
- 快照 GC：只保留最近 3 个版本，且保护当前版本与正在运行的版本。

**可观测性**

- 每轮构建写 `storage/projects/<id>/build-stats.jsonl`（路径/大小/token/错误码，不含文件内容或密钥）。
- `GET /api/health` 返回 DB、uptime、真实隔离级别与降级原因、worker 心跳、队列积压。
- `npm run stats -- <projectId>` 查看构建/token 指标 p50/p95。

### 2.9 工程质量与已知边界

**测试与 CI**

```bash
npm test                 # 70+ 单测：manifest/门禁/上下文/拆分/指标/预览令牌
npm run test:integration # 临时 DB 上的队列/事件/租约/重试
npm run test:sandbox     # Docker 契约：非 root、只读 rootfs、无宿主文件、注入无效、无外联
npm run test:e2e         # Web + worker + SSE 闭环
npm run lint / typecheck / build
```

CI 在 PR 上跑 lint、typecheck、单测、集成测试、生产构建与 E2E smoke；独立 `sandbox` job 跑 Docker 契约测试。

**已知边界（demo 级，生产化待办）**

| 边界 | 现状 | 生产化方向 |
|---|---|---|
| 认证 | 邮箱 + 密码；无邮箱验证、找回密码、二因子 | 接邮件服务 / OIDC / 2FA |

| 运维 | 手动/脚本启动 | 优雅停机、备份、多实例部署 |

## 4. 术语表

| 术语 | 含义 |
|---|---|
| Profile | 按网站类型预置的架构模板，约束模块划分与文件职责 |
| Manifest | 落盘的模块契约清单（路径、职责、exports、依赖、预算） |
| 结构门禁 | 在安装依赖前执行的确定性检查（大小/import 图/入口可达/漂移/ESM） |
| Context Assembler | 迭代时按需选择目标文件 + 依赖签名组装上下文的模块 |
| SEARCH/REPLACE | 基于精确匹配的增量代码编辑协议，优于整文件重写 |
| Race Mode | 同一 prompt 多模型并行生成、用户择优（atoms.dev 能力） |
| 暂存启动 | 新版本先起容器并健康检查，通过后原子切换流量 |
| 租约 / 心跳 | worker 领取任务的时效凭证，防止任务被重复执行或永久卡死 |
